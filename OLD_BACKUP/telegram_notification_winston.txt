✦ 📜 <b>Winston Logger Integration: Completed</b>

💬 <b>Permintaan/Pertanyaan:</b>
User ingin menggunakan Winston untuk logging pada sisi server, menggantikan console.log yang tidak production-ready. User meminta konfigurasi dengan max size 50KB dan max files 1 untuk file rotation.

🛠️ <b>Jawaban/Implementasi:</b>
Berhasil mengintegrasikan Winston logger dengan konfigurasi production-grade:
- Centralized logger utility di server/src/utils/logger.js
- Environment-aware formatting (colorized console untuk dev, JSON untuk prod)
- File transports dengan rotation (combined.log, error.log, exceptions.log, rejections.log)
- Exception handling untuk uncaught errors dan unhandled promise rejections
- Max file size 50KB dengan retention 1 file sesuai permintaan user
- Integrasi ke server.js menggantikan console.log/error

📜 <b>World Lore:</b>
Di tengah hiruk-pikuk Textical Engine, para Arsitek menyadari bahwa Chronicle of Events—catatan sejarah setiap peristiwa di dunia—hanya ditulis dengan tinta yang mudah pudar: console.log. Setiap kali server restart, seluruh memory dari pertempuran epik, transaksi ekonomi, dan kejadian langka lenyap begitu saja, seperti kabut pagi yang terkikis mentari.

Para Ancient Scribe yang menjaga Hall of Records menyadari bahwa mereka memerlukan sistem yang lebih permanen—sebuah Eternal Archive yang tidak hanya merekam, tetapi juga mengklasifikasikan peristiwa berdasarkan tingkat kepentingannya. Maka lahirlah Winston, sang Keeper of Eternal Logs. Winston memiliki kemampuan untuk mencatat setiap peristiwa dengan timestamp presisi, mengklasifikasikan berdasarkan severity (info, warn, error), dan yang terpenting—menyimpannya di Sacred Scrolls (log files) yang akan bertahan hingga akhir zaman (atau hingga 50KB, mana yang lebih dulu).

Kini, setiap Boss yang dikalahkan, setiap Guild yang terbentuk, setiap error yang muncul—semua tercatat dengan rapi di Archive Hall. Para Engineer dapat melihat kembali dengan jelas apa yang terjadi, bahkan setelah server restart berkali-kali. Sistem logging kini memiliki rotation otomatis, sehingga Archive tidak membengkak tak terkendali. Exception handler juga dipasang untuk menangkap error yang terlewat, memastikan tidak ada peristiwa penting yang hilang dari catatan sejarah Textical.
